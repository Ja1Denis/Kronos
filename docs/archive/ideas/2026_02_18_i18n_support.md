# Idea: Internationalization (i18n) Support

**Status:** 🌩️ Brainstorming (CONCLUDED)
**Date:** 2026-02-18
**Initiator:** User & Kronos

## 🚩 The Problem
Kronos uses hardcoded Croatian strings ("Greška", "Učitavam"). This limits global adoption.

## 💡 Selected Strategy: AI-Native Detection 🧠✨
Instead of manual config files, the LLM Installer detects the user's language naturally.

### How it works:
1.  **Installation Prompt:** Installer asks a standard question (e.g., "Ready to install?").
2.  **Detection:**
    - User says: "Može" -> **Croatian (HR)** detected.
    - User says: "Yes please" -> **English (EN)** detected.
    - User says: "OK" (Ambiguous) -> **English (EN)** default.
3.  **Action:** Installer sets `KRONOS_LANG=en` (or `hr`) in `.env`.
4.  **Runtime:** Kronos loads strings based on `.env`.

### 🛡️ Edge Case Handling ("OK" Problem)
If the user's input is ambiguous (e.g., "OK", "Hm", "1"):
- Default to **English**.
- Show message: *"Language set to English. To switch to Croatian, type `/lang hr`."*

## 📝 Implementation Plan (Next Steps)
1.  **Extract Strings:** Move hardcoded strings to `src/locales/strings.py` or JSON.
2.  **Config:** Add `KRONOS_LANG` support in `config.py`.
3.  **Installer Logic:** Add simple language detection heuristic (or LLM call) in installation script.
